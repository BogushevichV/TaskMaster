## 1. Роли пользователей

| Роль | Возможности |
|------|------------|
| **Менеджер** | Создание, редактирование, удаление задач; назначение сотрудников; просмотр всех задач; выгрузка отчётов (CSV/PDF). |
| **Сотрудник** | Просмотр назначенных задач; изменение статуса и заметок своих задач. |

Роль назначается при регистрации (`role: "manager"` или `role: "employee"`).

## 2. Запуск системы

### Бэкенд (сервер)

```bash
# 1. Поднять PostgreSQL
docker compose up -d

# 2. Перейти в папку бэкенда и создать .env
cd backend
copy .env.example .env   # Windows
# или: cp .env.example .env  (Linux/macOS)

# 3. Применить миграции
alembic upgrade head

# 4. Запустить API-сервер
uvicorn app.main:app --reload --app-dir .
```

API будет доступно по адресу: http://127.0.0.1:8000
Интерактивная документация: http://127.0.0.1:8000/docs

### Клиент (десктоп)

```bash
cd client
..\venv\Scripts\python.exe -m pip install -r requirements.txt
..\venv\Scripts\python.exe -m app.main
```

> Бэкенд должен быть запущен до старта клиента.

## 3. Вход в систему

1. Откройте клиент — появится окно входа.
2. Введите **имя пользователя** (username) и **пароль**.
3. Нажмите **Войти**.

Если сервер недоступен, приложение предложит использовать **локальный кэш** (офлайн-режим).

Зарегистрировать первого пользователя можно через API-документацию:
`POST /api/v1/auth/register`

## 4. Главное окно

```
┌─────────────────────────────────────────────────────────────────┐
│  [Статус ▼] [Ответственный ▼]  С: [дата]  По: [дата]  [Поиск]  │  ← Фильтры
│  [Обновить] [Синхронизировать] [Новая задача] [Ред.] [Удалить]  │  ← Панель инструментов
│  ┌──────────────────────────────────────────────────────────┐   │
│  │ Название   │ Статус    │ Дедлайн         │ Ответств. │ S │   │  ← Таблица задач
│  │ ...        │ ...       │ ...             │ ...       │   │   │
│  └──────────────────────────────────────────────────────────┘   │
│  Иванов И.И. (manager) — задач: 12                  Онлайн      │  ← Статус-бар
└─────────────────────────────────────────────────────────────────┘
```

**Колонка S (Sync)** — статус синхронизации:
- `synced` — запись актуальна
- `pending` — ожидает отправки на сервер (значок ⏳ в названии)

## 5. Работа с задачами

### Создать задачу (только менеджер)

1. Нажмите **Новая задача**.
2. Заполните поля: название, описание, статус, дедлайн, ответственный.
3. Нажмите **Сохранить**.

### Редактировать задачу

1. Выберите строку в таблице.
2. Нажмите **Редактировать** (или дважды щёлкните строку).
3. Менеджер может изменить любые поля; сотрудник — только статус и заметки.
4. Нажмите **Сохранить**.

### Удалить задачу (только менеджер)

1. Выберите задачу.
2. Нажмите **Удалить** и подтвердите.

### Статусы задач

| Статус | Описание |
|--------|----------|
| Новая | Задача создана, не взята в работу |
| В работе | Сотрудник приступил к выполнению |
| Выполнена | Задача завершена |
| Отменена | Задача отменена менеджером |

## 6. Офлайн-режим

Если сервер недоступен:
- В строке состояния отображается **«Офлайн»** красным цветом.
- Изменения задач сохраняются в **локальной SQLite-базе** со статусом `pending`.
- При восстановлении соединения фоновый поток автоматически синхронизирует изменения.
- Кнопка **Синхронизировать** запускает синхронизацию вручную.

При конфликтах (одна задача изменена и на сервере, и локально) применяется правило **LWW (Last Write Wins)** — побеждает более поздняя запись. Список конфликтов отображается в диалоге.

## 7. Отчёты

Доступно только менеджерам через REST API (или интерфейс Swagger `/docs`):

| Эндпоинт | Описание |
|----------|----------|
| `GET /api/v1/reports/tasks/pdf` | Скачать PDF-отчёт по задачам |
| `GET /api/v1/reports/tasks/csv` | Скачать CSV-отчёт по задачам |

Параметры запроса (опционально):
- `date_from` — начало периода (ISO 8601)
- `date_to` — конец периода (ISO 8601)

Отчёт содержит: количество созданных задач, выполненных в срок, просроченных, а также таблицу задач.

## 8. Сброс пароля

### Шаг 1 — запросить токен

```
POST /api/v1/auth/password-reset/request
Content-Type: application/json

{ "email": "user@example.com" }
```

Если указанный email зарегистрирован, на него придёт письмо с токеном.
В режиме разработки (SMTP не настроен) токен возвращается прямо в теле ответа (`dev_token`).

### Шаг 2 — установить новый пароль

```
POST /api/v1/auth/password-reset/confirm
Content-Type: application/json

{
  "token": "<токен из письма>",
  "new_password": "новый_пароль"
}
```

Токен действителен **1 час**.

### Настройка SMTP (для администратора)

В файле `backend/.env` укажите:

```env
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=noreply@example.com
SMTP_PASSWORD=secret
SMTP_FROM=noreply@example.com
```

## 9. Значок в трее

После входа в систему в области уведомлений появляется значок **TaskMaster**.

| Действие | Результат |
|----------|-----------|
| Двойной клик | Открыть главное окно |
| Правый клик → «Открыть TaskMaster» | Открыть главное окно |
| Правый клик → «Выйти» | Завершить приложение |

**Всплывающие уведомления:**

| Событие | Сообщение |
|---------|-----------|
| Синхронизация завершена | «Синхронизировано изменений: N» |
| Обнаружены конфликты | «Конфликтов: N. Применено правило LWW» |
| Переход в офлайн | «Соединение потеряно. Изменения сохраняются локально» |
| Восстановление связи | «Соединение восстановлено. Запуск синхронизации...» |
